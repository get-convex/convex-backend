This page builds on the core
[Queries, Mutations & Actions](/client/svelte/reactivity.mdx) API. Make sure
`setupConvex()` is in your root layout before using these features — see
[Overview](/client/svelte/overview.mdx#setup).

Import from `convex-svelte/sveltekit` for SvelteKit-specific features: SSR
transport with live upgrade, and a server-side HTTP client helper.

<Admonition type="info" title="Why bother with SSR on a realtime backend?">

The client will open a WebSocket and get live updates anyway — so is SSR worth
it? Almost always yes: it's faster for time-to-data on first page load. See
[Why server-side rendering with Convex?](/client/svelte/why-server-rendering.mdx)
for the full comparison.

</Admonition>

## SSR with convexLoad / convexLoadPaginated (recommended)

`convexLoad()` and `convexLoadPaginated()` fetch data on the server and
automatically upgrade to live subscriptions on the client. No manual
`initialData` wiring needed. Use `convexLoad()` for regular queries and
`convexLoadPaginated()` for paginated queries.

### Setup

`convex-svelte/sveltekit` requires SvelteKit 2.12 or later, including
SvelteKit 3.

Add `initConvex()` and the transport hooks to `hooks.ts` (universal hooks — runs
on both server and client). `initConvex()` creates the `ConvexClient` singleton
early so the transport decoder can upgrade SSR data to live subscriptions.
`setupConvex()` in your root layout automatically reuses this singleton.

Client options only take effect where the client is created, like the
`ConvexReactClient` constructor in React. Pass them to
`initConvex(PUBLIC_CONVEX_URL, options)`: `setupConvex()` reuses that client and
ignores options passed to it.

If you only use `convexLoad()`, you only need the `ConvexLoadResult` transport.
Add `ConvexLoadPaginatedResult` when using `convexLoadPaginated()`.

```ts title="src/hooks.ts"
import {
  initConvex,
  encodeConvexLoad,
  decodeConvexLoad,
  encodeConvexLoadPaginated,
  decodeConvexLoadPaginated,
} from "convex-svelte/sveltekit";
import { PUBLIC_CONVEX_URL } from "$env/static/public";

initConvex(PUBLIC_CONVEX_URL);

export const transport = {
  ConvexLoadResult: {
    encode: encodeConvexLoad,
    decode: decodeConvexLoad,
  },
  // Only needed if you use convexLoadPaginated()
  ConvexLoadPaginatedResult: {
    encode: encodeConvexLoadPaginated,
    decode: decodeConvexLoadPaginated,
  },
};
```

If you call `convexLoad()` in universal load functions (`+page.ts`,
`+layout.ts`), also add the `convexLoadHydration` handle to `hooks.server.ts`.
It requires SvelteKit 2.56 or later and doesn't support SvelteKit 3 yet (see
[convexLoadHydration](#convexloadhydration)):

```ts title="src/hooks.server.ts"
import { convexLoadHydration } from "convex-svelte/sveltekit/server/hydration";

export const handle = convexLoadHydration;
```

and a `%convex.hydration%` placeholder to the `<head>` of `src/app.html`, where
the handle puts the results:

```html title="src/app.html"
<head>
  %sveltekit.head% %convex.hydration%
</head>
```

SvelteKit runs universal load functions on the server and then
[again in the browser during hydration](https://svelte.dev/docs/kit/load#Universal-vs-server).
That second run happens before `setupAuth()` in your root layout has
authenticated the client. The handle embeds the server's `convexLoad()` results
in the HTML, and the browser reuses them instead of querying Convex again. That
way authenticated data stays authenticated, and the page becomes interactive
without waiting for the WebSocket. The live subscription starts once auth is set
up. To combine the handle with your own, use
[`sequence()`](https://svelte.dev/docs/kit/@sveltejs-kit-hooks#sequence), as in
[Authenticated fetches](#authenticated-fetches).

### Usage with convexLoad

```ts title="src/routes/+page.ts"
import { convexLoad } from "convex-svelte/sveltekit";
import { api } from "$convex/_generated/api";

export const load = async () => ({
  tasks: await convexLoad(api.tasks.get, {}),
});
```

```svelte title="src/routes/+page.svelte"
<script lang="ts">
  let { data } = $props();
  const tasks = $derived(data.tasks);
</script>

{#if tasks.isLoading}
  Loading...
{:else if tasks.error}
  Error: {tasks.error.message}
{:else}
  <ul>
    {#each tasks.data as task}
      <li>{task.text}</li>
    {/each}
  </ul>
{/if}
```

The result has the same shape as `useQuery()` — `.data`, `.isLoading`, `.error`,
`.isStale` — and is reactive. On first load, data arrives via SSR (no loading
flash). After hydration, a live WebSocket subscription takes over automatically.

### Usage with convexLoadPaginated

`convexLoadPaginated()` works the same way but for paginated queries. It fetches
the first page on the server and upgrades to a live paginated subscription on
the client — with `loadMore()` support for incremental loading.

```ts title="src/routes/+page.ts"
import { convexLoadPaginated } from "convex-svelte/sveltekit";
import { api } from "$convex/_generated/api";

export const load = async () => ({
  messages: await convexLoadPaginated(
    api.messages.paginatedList,
    { searchWords: [] },
    { initialNumItems: 10 },
  ),
});
```

```svelte title="src/routes/+page.svelte"
<script lang="ts">
  let { data } = $props();
  const messages = $derived(data.messages);
</script>

{#if messages.isLoading}
  Loading...
{:else if messages.error}
  Error: {messages.error.message}
{:else}
  <ul>
    {#each messages.results as message}
      <li>{message.author}: {message.body}</li>
    {/each}
  </ul>
  {#if messages.status === "CanLoadMore"}
    <button onclick={() => messages.loadMore(10)}>Load more</button>
  {/if}
{/if}
```

The result has the same shape as `usePaginatedQuery()` — `.results`, `.status`,
`.isLoading`, `.error`, `.loadMore()` — and is reactive. On first load, the
first page arrives via SSR (no loading flash). After hydration, a live WebSocket
subscription takes over and `loadMore()` becomes functional.

### Authenticated fetches

For authenticated SSR fetches, use `withServerConvexToken` in your server hook.
This stores the auth token per-request via `AsyncLocalStorage`, so `convexLoad`
and `createConvexHttpClient` pick it up automatically — no `{ token }` option
needed.

```ts title="src/hooks.server.ts"
import type { Handle } from "@sveltejs/kit";
import { sequence } from "@sveltejs/kit/hooks";
import { withServerConvexToken } from "convex-svelte/sveltekit/server";
import { convexLoadHydration } from "convex-svelte/sveltekit/server/hydration";

const convexAuth: Handle = async ({ event, resolve }) => {
  const token = await getAuthToken(event.cookies); // your auth provider
  event.locals.token = token;
  return withServerConvexToken(token, () => resolve(event));
};

export const handle = sequence(convexLoadHydration, convexAuth);
```

Then use `convexLoad` in **any** load function — `+page.ts` or
`+page.server.ts`:

```ts title="src/routes/+page.ts"
// Universal — works for both SSR and client-side navigation
import { convexLoad } from "convex-svelte/sveltekit";
import { api } from "$convex/_generated/api";

export const load = async () => ({
  tasks: await convexLoad(api.tasks.get, {}),
});
```

The explicit `{ token }` option still works as a manual override:

```ts title="src/routes/+page.server.ts"
// Explicit token (escape hatch)
export const load = async ({ locals }) => ({
  tasks: await convexLoad(api.tasks.get, {}, { token: locals.token }),
});
```

### Skipping queries

Pass `'skip'` as args to avoid fetching — useful for auth-gated queries that
should not run when the user is unauthenticated:

```ts title="src/routes/+page.server.ts"
// Skip when unauthenticated
export const load = async ({ locals }) => ({
  user: await convexLoad(api.users.get, locals.token ? {} : "skip"),
});
```

When skipped, `convexLoad` returns
`{ data: undefined, isLoading: false, error: undefined, isStale: false }`
without making any request. `convexLoadPaginated` returns
`{ results: [], status: 'Exhausted', isLoading: false, error: undefined, loadMore: () => false }`.

### Choosing between `+page.ts` and `+page.server.ts`

`convexLoad` works in both universal (`+page.ts`) and server-only
(`+page.server.ts`) load functions. The difference is what happens during
**client-side navigation** (after the first SSR page load):

- **`+page.ts` (universal):** On client-side navigation, `convexLoad` runs in
  the browser and subscribes to Convex directly — no server roundtrip. Auth is
  handled implicitly via the already-authenticated `ConvexClient` singleton
  (configured by `setupAuth()` in your root layout). On the first page load, the
  browser reuses the server's result during hydration, as long as
  [`convexLoadHydration`](#setup) is set up.
- **`+page.server.ts` (server-only):** On client-side navigation, SvelteKit
  fetches from your server, which then queries Convex — adding an extra network
  hop. Auth is always explicit (server-side via `withServerConvexToken` or
  `locals.token`).

Both produce identical SSR on first page load. Use `+page.ts` for best
navigation performance. Use `+page.server.ts` if you need access to server-only
data (e.g. `locals`, cookies) or prefer explicit auth handling.

<Admonition type="caution" title="+page.ts without convexLoadHydration">

Without the `convexLoadHydration` handle, the hydration run of a `+page.ts` load
queries Convex before `setupAuth()` has authenticated the client. Auth-protected
queries then return their unauthenticated result (or fail the load) until the
live subscription catches up. This includes SvelteKit 3, where the handle isn't
supported yet: load data that needs auth in `+page.server.ts` there.

</Admonition>

### Subscription lifecycle

Queries created by `convexLoad()` and `convexLoadPaginated()` are scoped to the
route. A query stays subscribed while the current route uses it, meaning it's
reachable from `page.data` (every layout plus the current page) or rendered by a
component. Once you navigate away, the query is released.

A released query doesn't unsubscribe right away. It waits in a small idle
buffer, so revisiting a page reuses the live subscription instead of subscribing
again. In a universal `+page.ts`, that also makes the revisit instant: the load
gets its data from the live subscription without a round trip. A revisited
`convexLoadPaginated()` query also keeps the pages loaded with `loadMore()`.
Server-only loads (`+page.server.ts`) still fetch through your server on each
navigation.

The query unsubscribes once newer idle queries push it out of the buffer
(`maxIdleEntries`, oldest first) or it has been idle for `expiration`
milliseconds. If a page uses it again later, it resubscribes automatically.

Configure the buffer with the `queryCache` option of `initConvex()`. The option
names match convex-helpers'
[`ConvexQueryCacheProvider`](https://github.com/get-convex/convex-helpers/tree/main/packages/convex-helpers#query-caching):

```ts title="src/hooks.ts"
initConvex(PUBLIC_CONVEX_URL, {
  // The defaults. Pass `queryCache: false` to unsubscribe as soon as a route
  // stops using a query.
  queryCache: { maxIdleEntries: 10, expiration: 60_000 },
});
```

To skip the buffer for a single query, for example one that's expensive to keep
running, pass `keepAlive: false` to `convexLoad()` or `convexLoadPaginated()`:

```ts title="src/routes/+page.ts"
export const load = async () => ({
  feed: await convexLoad(api.feed.live, {}, { keepAlive: false }),
});
```

To stop a subscription yourself, call `dispose()` on the result. A disposed
query never resubscribes.

A few details:

- Queries that no route ever uses, such as a
  [preload](https://svelte.dev/docs/kit/link-options#data-sveltekit-preload-data)
  for a link you never click, close 5 seconds after their first result arrived.
  They never take a slot in the idle buffer, so hovering over links can't push
  out pages you visited. Clicking such a link later just resubscribes.
- After a `convexLoad()` query unsubscribes, `.isStale` is `true` and `.data`
  keeps the last known value until it resubscribes. A `convexLoadPaginated()`
  query keeps its last `.results`. After `dispose()`, its `loadMore()` returns
  `false`.
- `useQuery()` and `usePaginatedQuery()` aren't affected. They unsubscribe when
  their component unmounts.

## SSR with initialData (manual alternative)

If you prefer server-only load functions (`+page.server.ts`) or need more
control, you can use the `initialData` option on `useQuery()` and
`usePaginatedQuery()` directly.

```ts title="src/routes/+page.server.ts"
import { ConvexHttpClient } from "convex/browser";
import type { PageServerLoad } from "./$types.js";
import { PUBLIC_CONVEX_URL } from "$env/static/public";
import { api } from "../convex/_generated/api.js";

export const load = (async () => {
  const client = new ConvexHttpClient(PUBLIC_CONVEX_URL!);
  return {
    messages: await client.query(api.messages.list, { searchWords: [] }),
  };
}) satisfies PageServerLoad;
```

```svelte title="src/routes/+page.svelte"
<script lang="ts">
  import type { PageData } from "./$types.js";
  let { data }: { data: PageData } = $props();

  import { useQuery } from "convex-svelte";
  import { api } from "../convex/_generated/api.js";

  const messages = useQuery(
    api.messages.list,
    () => ({ searchWords: [] }),
    () => ({ initialData: data.messages }),
  );
</script>
```

Combining `initialData` with `keepPreviousData: true` (or never changing the
query arguments) should be enough to avoid ever seeing a loading state.

<Admonition type="note" title="When to use this over convexLoad">

Use `initialData` when building a library that needs to support Svelte-only,
SvelteKit SPA, and SvelteKit SSR without requiring the transport hook setup.

</Admonition>

## Server helpers

These are server-only helpers (`hooks.server.ts`, `+page.server.ts`, form
actions, endpoints) for authenticating SSR fetches and running one-off calls
from the server. For one-off calls from the **client**, use
[`getConvexClient()`](/client/svelte/reactivity.mdx#one-time-calls) instead.

### withServerConvexToken (recommended)

Import from `convex-svelte/sveltekit/server`. Wraps your SvelteKit `resolve()`
call to store the auth token per-request via `AsyncLocalStorage`. Both
`convexLoad` and `createConvexHttpClient` automatically read it during SSR.

```ts title="src/hooks.server.ts"
import type { Handle } from "@sveltejs/kit";
import { withServerConvexToken } from "convex-svelte/sveltekit/server";

export const handle: Handle = async ({ event, resolve }) => {
  const token = await getAuthToken(event.cookies);
  event.locals.token = token; // still available for direct use
  return withServerConvexToken(token, () => resolve(event));
};
```

```ts title="src/app.d.ts"
declare global {
  namespace App {
    interface Locals {
      token: string | undefined;
    }
  }
}
```

With this setup, `convexLoad()` and `createConvexHttpClient()` automatically
authenticate during SSR — no `{ token }` option needed in load functions.

### convexLoadHydration

Import from `convex-svelte/sveltekit/server/hydration`; requires SvelteKit 2.56
or later. A SvelteKit `handle` that embeds the `convexLoad()` and
`convexLoadPaginated()` results of universal load functions in the
server-rendered HTML, so the load's re-run during hydration reuses them. See
[Setup](#setup) for why this matters.

- It needs a `%convex.hydration%` placeholder in the `<head>` of `src/app.html`
  (see [Setup](#setup)). Without it, nothing is embedded and a warning in
  development says so.
- Everything `convexLoad()` fetches while a universal load (`+page.ts`,
  `+layout.ts`) runs is embedded, including calls in helpers the load invokes,
  but not calls inside
  [remote functions](https://svelte.dev/docs/kit/remote-functions). Pass
  `{ hydrate: false }` for a result that must not reach the browser, e.g. one
  fetched for the server to pick a few fields from.
- Server loads (`+page.server.ts`) never contribute, not even results they only
  use internally. The results they return reach the browser through the
  transport hook.
- Await `convexLoad()` in universal loads. A streamed (not awaited) result is
  only embedded if it finished before the page HTML was generated; otherwise its
  hydration run queries Convex before `setupAuth()`. In development, a console
  warning points out loads that find no embedded result.
- With `{ hydrate: false }` (e.g. for a large result), that load queries Convex
  during hydration, before `setupAuth()`, like without the handle.
- Results are only reused while the initial page hydrates. Client-side
  navigations always subscribe to Convex.
- Pages without embedded results, e.g. with `ssr = false`, get no payload and no
  warnings. If an embedded result can't be read, that load queries Convex
  instead.
- The handle relies on SvelteKit 2 marking universal loads and remote functions
  on the server. SvelteKit 3 no longer marks universal loads, so the handle
  can't tell them apart from server loads: it embeds nothing there and logs a
  warning. The same happens if it can't read the markers for another reason.

### Setting up `locals.token` (without withServerConvexToken)

If you prefer not to use `withServerConvexToken`, you can still extract the
token and pass it explicitly:

```ts title="src/hooks.server.ts"
import type { Handle } from "@sveltejs/kit";

export const handle: Handle = async ({ event, resolve }) => {
  event.locals.token = await getAuthToken(event.cookies);
  return resolve(event);
};
```

Then pass `{ token: locals.token }` to `convexLoad` or `createConvexHttpClient`
in each load function.

### createConvexHttpClient

For server-only code (`+page.server.ts`, form actions, API routes), use
`createConvexHttpClient()`:

```ts title="src/routes/+page.server.ts"
// With withServerConvexToken (no args needed)
import { createConvexHttpClient } from "convex-svelte/sveltekit";
import { api } from "$convex/_generated/api";

export const load = async () => {
  const client = createConvexHttpClient();
  const tasks = await client.query(api.tasks.get, {});
  return { tasks };
};
```

Explicit token still works as an override:

```ts title="src/routes/+page.server.ts"
// Explicit token (escape hatch)
export const load = async ({ locals }) => {
  const client = createConvexHttpClient({ token: locals.token });
  const tasks = await client.query(api.tasks.get, {});
  return { tasks };
};
```

The `url` option falls back to the URL set by `initConvex()`.

## API reference

Functions and types exported from `convex-svelte/sveltekit`:

| Export                                      | Kind     | Description                                                                                |
| ------------------------------------------- | -------- | ------------------------------------------------------------------------------------------ |
| `initConvex(url, options?)`                 | Function | Create the `ConvexClient` singleton early. Only needed for [convexLoad SSR setup](#setup). |
| `getConvexUrl()`                            | Function | Retrieve the deployment URL set by `initConvex()` or `setupConvex()`.                      |
| `closeConvex()`                             | Function | Close the app-scoped client and clear the singleton (also exported from `convex-svelte`).  |
| `convexLoad(query, args, options?)`         | Function | Fetch data server-side, upgrade to live subscription on client.                            |
| `encodeConvexLoad`                          | Function | Transport encoder — use in `hooks.ts` (see [Setup](#setup)).                               |
| `decodeConvexLoad`                          | Function | Transport decoder — use in `hooks.ts` (see [Setup](#setup)).                               |
| `convexLoadPaginated(query, args, options)` | Function | Fetch first page server-side, upgrade to live paginated subscription on client.            |
| `encodeConvexLoadPaginated`                 | Function | Paginated transport encoder — use in `hooks.ts`.                                           |
| `decodeConvexLoadPaginated`                 | Function | Paginated transport decoder — use in `hooks.ts`.                                           |
| `createConvexHttpClient(options?)`          | Function | Create a `ConvexHttpClient` for server-side use.                                           |
| `CreateConvexHttpClientOptions`             | Type     | Options for `createConvexHttpClient`: `url`, `token`, `options`.                           |
| `InitConvexOptions`                         | Type     | `ConvexClientOptions` plus [`queryCache`](#subscription-lifecycle) for `initConvex`.       |
| `QueryCacheOptions`                         | Type     | Idle buffer settings: `maxIdleEntries` (default `10`), `expiration` (default `60_000`).    |

The server-only helper `withServerConvexToken` is imported from
`convex-svelte/sveltekit/server`, and
[`convexLoadHydration`](#convexloadhydration) from
`convex-svelte/sveltekit/server/hydration`.
